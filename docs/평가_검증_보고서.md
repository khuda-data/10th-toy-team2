## 1. 핵심 결론 — 발표 헤드라인

**독립 경로(학습 미사용)에서 WalkFit은 기존 지도앱 방식 대비 도착시간 오차를 61% 줄인다.**

| 지표 | 정속 4km/h (기존 지도앱) | WalkFit (경사+개인화) |
|---|---|---|
| 경로 ETA 오차 (MAE) | 38.1초 ± 3.4 | **14.7초 ± 1.6** |
| 경로 ETA 오차율 (MAPE) | 21.3% | **7.1%** |

- 평가 방식: 회차(파일) 단위 홀드아웃 20%, seed 10회 반복 평균
- 통계적 유의성: 대응표본 t-검정 p = 5.2e-04, Wilcoxon p = 1.6e-03 (n=25 경로)
- **신호대기 미포함 수치** — 학습 경로 49개 중 횡단보도를 지나는 경로가 0개여서 신호 효과를 반영·검증할 수 없었다(7절)

## 2. 통합 결과물 — ETA 엔진 (`src/eta.py`)

세 파트의 산출물을 하나의 함수로 조립했다.

```
ETA = Σ [ dist_m / (v_user × k_slope(slope_pct)) ] + Σ 신호대기
        └── 속도 모델 ──┘                            └ 신호 모델 ┘
```

| 항목 | 처리 |
|---|---|
| k_slope | `models/k_slope_model_v2.json` 자동 인식, 없으면 v1 fallback |
| v_user | `models/v_user_v2.csv` |
| 외삽 방지 | 경사도를 `valid_slope_range`로 클립 후 배율 [0.3, 1.4] 제한 (v2 문서 규약 준수) |
| 신호대기 | `data/processed/영통구_횡단보도별_신호대기.csv`(351개 지점) 자동 인식, 없으면 0초로 동작 |
| 신규 사용자 | v_user에 없는 사람은 팀 평균 속도로 fallback |

동작 예시 (김재형\_급경사내리막\_1회차, 161m):
```
실측 115초 | WalkFit 116초 (오차 1초) | 정속 4km/h 145초 (오차 30초)
```

### 신호대기 연동 (완료)

신호대기 산출물 `data/processed/영통구_횡단보도별_신호대기.csv`(351개 지점, 신호 있는 곳 300개)를 엔진에 연결했다. 컬럼명이 사전 합의안(`crossing_id, lat, lon, cycle_C_s, red_R_s`)과 달라(`횡단보도관리번호, 위도, 경도, 주기_s, 적색_R_s`) 한글 스키마도 인식하도록 수정했으며, 이미 산출된 `기대대기_s`를 그대로 사용한다.

엔진은 경로 구간 경계가 횡단보도 반경 25m 내를 지나면 해당 지점 기대대기를 합산한다.

## 3. 검증 방법론 — 두 가지 누수 차단

기존 문서의 모든 R²는 in-sample(학습 데이터 자기 채점)이었다. 이를 out-of-sample 평가로 대체하면서 두 가지 데이터 누수를 차단했다.

**(1) 분할 단위를 구간이 아닌 회차(파일)로.** 같은 GPX 파일의 인접 구간은 같은 날·같은 길·같은 컨디션이라 강하게 상관된다. 구간을 랜덤 분할하면 train에 있는 구간의 바로 옆 구간이 test에 들어가 성능이 과대평가된다. 파일 단위로 분리해야 "처음 걷는 길"에 대한 성능이 된다.

**(2) 파이프라인 전체를 train만으로 재적합.** 배포된 `v_user_v2.csv`를 그대로 쓰면 그 값 자체가 test 구간까지 포함해 계산된 것이라 누수다. 매 분할마다 평지속도 → 균형표본 → k_slope → v_user를 train 세트만으로 다시 계산한 뒤 test를 평가한다.

## 4. 구간 단위 검증 — 개인화가 실제로 기여하는가

회차 단위 홀드아웃, 10-seed 평균 구간속도 MAE (m/s, 낮을수록 좋음):

| 방식 | MAE | 의미 |
|---|---|---|
| 정속 4km/h | 0.2660 ± 0.0150 | 기존 지도앱 |
| (a) 공통곡선만 | 0.1674 ± 0.0094 | 경사만 반영, 개인화 없음 |
| **(b) v2 개인화** | **0.1601 ± 0.0086** | 현재 채택 모델 |
| (c) shrinkage 적용 | 0.1611 ± 0.0090 | 축소추정 변형 |

**개인화는 실제로 기여한다.** (a) 0.1674 → (b) 0.1601. 진행기록 7절에서 제기된 "v_user가 v_flat_raw와 근접해 개인화 효과가 사라질 가능성"은 out-of-sample에서도 개선이 유지되므로 해당하지 않는 것으로 확인됐다.

## 4-1. Shrinkage(계층적 축소추정) — 표본 크기별 손익분기점

당초 기획의 계층적 축소추정을 (c)로 구현해 비교한 결과 (b)보다 나아지지 않았다. 다만 **"한 데이터셋에서 개선이 없다"는 이유만으로 방법론을 폐기하는 것은 부당**하므로, 표본 크기를 인위적으로 줄여가며 shrinkage가 유효해지는 조건을 탐색했다.

**실험**: 각 사람의 train 구간을 5·10·30개로 제한한 뒤, shrinkage 적용/미적용의 test MAE를 20-seed 대응표본 t-검정으로 비교.

| 사람당 train 표본 | shrinkage 없음 | shrinkage 있음 | 차이 | p-value | 판정 |
|---|---|---|---|---|---|
| **현재(72~363개)** | **0.1674** | 0.1714 | −0.0039 | <0.001 | 미적용이 유의하게 우세 |
| 30개 | 0.1688 | 0.1729 | −0.0041 | <0.001 | 미적용이 유의하게 우세 |
| 10개 | 0.1704 | 0.1737 | −0.0033 | 0.057 | 구분 불가 |
| 5개 | 0.1895 | **0.1858** | **+0.0038** | 0.061 | 부호 역전 — 적용이 우세한 경향 |

(차이 = 미적용 − 적용. 양수면 shrinkage가 유리)

**결론.** 표본이 줄어들수록 shrinkage의 상대적 성능이 단조 개선되며, **5개 구간 부근에서 부호가 역전**된다(−0.0039 → −0.0041 → −0.0033 → **+0.0038**). 즉 shrinkage는 표본이 극히 적을 때 유효한 방법이고, 손익분기점은 **사람당 약 5~10개 구간** 사이다. 본 프로젝트는 최소 72개(train 기준)로 이 지점을 크게 상회하므로, 팀 평균으로 끌어당기는 보정이 오히려 개인 실측값을 왜곡한다.

(다만 5·10개 조건의 p-value가 0.06 수준으로 통상적 유의수준에 미달하므로, "부호가 역전되는 경향을 확인했다"까지가 정확한 진술이며 "5개에서 shrinkage가 유의하게 낫다"고 단정하지 않는다.)

> **채택 결정**: 현재 데이터에는 shrinkage를 **미적용**한다(v2 방식 유지).
> **확장 권고**: 서비스화 시 신규 사용자처럼 측정 이력이 10개 미만인 경우에는 shrinkage를 적용하는 이원 설계가 타당하다. 즉 shrinkage는 "틀린 방법"이 아니라 "적용 조건이 있는 방법"이며, 본 실험으로 그 조건을 정량화했다.

재현: `python -m src.evaluate_internal --shrinkage-curve --n-seeds 20`

## 4-2. 개인 데이터량에 따른 학습곡선 — 더 걸으면 무엇이 좋아지는가

윤예진·홍민기 두 참여자는 다른 인원(89~97개)보다 많은 데이터를 수집했다(146개·454개). "데이터가 쌓이면 개인화가 좋아진다"는 기획 가설을 이 불균형 구도로 검증했다.

**실험 설계**: 대상자의 파일 20%를 test로 고정하고, 남은 train에서 n개를 무작위 추출해 `v_user`를 추정한 뒤 test 구간속도 예측오차를 측정한다. 공통 `k_slope` 곡선은 **대상자를 제외한 나머지 인원 데이터로 고정**해, 개인 표본 수의 효과만 분리했다. 같은 n을 40-seed 반복했을 때 `v_user` 추정값이 흔들리는 정도(표준편차)를 1.2km 경로 ETA의 ±초로 환산해 신뢰구간으로 삼았다.

### 결과 — 정확도는 포화, 신뢰도는 계속 개선

| 홍민기 (보유 454개) | 예측오차 MAE | ETA 신뢰구간 |
|---|---|---|
| 0개 (팀평균) | 0.2224 | — |
| 5개 | 0.2235 | ± 69초 |
| 30개 | 0.2123 | ± 34초 |
| 90개 *(타 인원 수준)* | 0.2113 | ± 17초 |
| 250개 | 0.2113 | ± 10초 |
| **454개 (현재)** | 0.2121 | **± 8초** |

| 윤예진 (보유 146개) | 예측오차 MAE | ETA 신뢰구간 |
|---|---|---|
| 0개 (팀평균) | 0.1375 | — |
| 5개 | 0.1585 | ± 56초 |
| 30개 | 0.1381 | ± 20초 |
| 90개 | 0.1357 | ± 11초 |

**확인된 사실 두 가지**

1. **예측오차는 약 20~30개 구간에서 포화된다.** `v_user`는 평균 하나를 추정하는 값이므로 표준오차가 1/√n으로 수렴하며, 30개면 평균값 자체는 충분히 잡힌다. 추가 수집이 예측값을 더 정확하게 만들지는 않는다.
2. **반면 추정의 신뢰도는 계속 개선된다.** 홍민기의 ETA 신뢰구간은 5개일 때 ±69초에서 454개에서 **±8초로 88% 축소**됐다(윤예진 ±56초 → ±11초). 데이터를 더 모아서 얻는 것은 "더 정확한 값"이 아니라 **"그 값을 더 확신할 수 있다"**는 점이다.

이는 서비스 관점에서 의미가 있다. 이용 이력이 적은 사용자에게는 "약 15분"으로, 이력이 충분한 사용자에게는 "15분 ±8초"로 제시하는 등 **불확실성을 함께 표현하는 근거**가 된다.

### 개인화의 가치는 데이터 양보다 '평균에서의 이탈'이 결정한다

팀 평균만 쓴 경우(n=0) 대비 개인화 적용 시의 개선율:

| 참여자 | v_user | 팀평균과 차이 | 팀평균 MAE | 개인화 MAE | 개선 |
|---|---|---|---|---|---|
| **최희수** | 1.627 | **+18.3%** | 0.3001 | 0.1316 | **+56%** |
| 김재형 | 1.294 | −5.9% | 0.1832 | 0.1645 | +10% |
| 홍민기 | 1.332 | −3.1% | 0.2224 | 0.2113 | +5% |
| 박준서 | 1.301 | −5.4% | 0.1184 | 0.1072 | +9% |
| 윤예진 | 1.335 | −2.9% | 0.1375 | 0.1357 | +1% |
| 권동하 | 1.360 | −1.1% | 0.1148 | 0.1136 | +1% |

최희수는 **5개 구간만으로 오차를 56% 줄였다**(0.3001 → 0.1364). 반면 팀 평균에 가까운 인원은 데이터를 아무리 모아도 개선이 1~5%에 그친다. 즉 개인화가 필요한 대상은 "많이 걸은 사람"이 아니라 **"평균과 다른 사람"**이다.

재현: `python -m src.evaluate_internal --learning-curve --n-seeds 40`
(원자료: `data/processed/eval_learning_curve.csv`)

## 5. v1 vs v2 비교 — 어느 버전을 쓸 것인가

v2(1차식 + 경사보정 v_user)를 그대로 채택하지 않고 독립 평가했다.

| 모델 | 경로 MAE | 경로 MAPE |
|---|---|---|
| v1 (2차식 + shrinkage) | 15.3초 | 7.1% |
| **v2 (1차식 + 경사보정)** | **15.2초** | **7.1%** |

성능이 동등하면서 v2가 더 단순하고(1차식) 검증 방법이 더 정직하므로(CV 기반) **v2 채택이 타당함을 확인**했다. 통합 엔진은 v2를 기본값으로 사용한다.

## 6. 검증 데이터 수집 설계 (확정)

**독립된 편도 경로 2개**를 팀원 6명이 각각 2회씩 걷는다. 총 **24개 GPX**를 수집한다. 수집 절차·기록지는 팀 노션의 「검증용 데이터 수집 가이드」 참조.

| | 경로 A | 경로 B |
|---|---|---|
| 출발 | 경희대학교 공과대학 정문 | 영통역 1번 출구 앞 |
| 도착 | 영통역 2번 출구 앞 | 레이지하우스 카페 |
| 거리 | 약 1.2km (네이버 안내 18분) | 답사 후 확정 |
| 신호 횡단보도 | 3개 | 답사 후 확정 |

**네이버 방식 확인**: 경로 A의 네이버 도보 안내값 1.2km = 18분을 역산하면 정확히 **1.111 m/s = 시속 4.00km**이며 신호대기는 가산되지 않는다. 본 보고서가 비교 기준으로 삼은 "정속 4km/h"가 실제 상용 서비스와 일치함이 확인되었다.

**경로 2개 설계의 이점**

경로가 1개면 그 경로만의 고유 오차(공사·인도 폭·해당 신호의 실제 주기 편차)와 모델 오차가 교란되어 분리할 수 없다. 측정을 아무리 늘려도 전부 같은 경로를 공유하므로 독립 표본이 아니다.

경로 2개에서는 오차 방향이 **두 경로에서 일관되면 모델 편향**, **갈리면 경로 특성**으로 판별할 수 있다. 검출력도 개선된다.

| 설계 | 측정 수 | 검출력(경로오차 ±25초) | 검출력(±50초) |
|---|---|---|---|
| 경로 1개 × 6명 × 2회 | 12 | 92% | 83% |
| **경로 2개 × 6명 × 2회** | **24** | **99%** | **88%** |

**남은 한계**

- 두 경로 모두 영통구 내 유사 지형이므로, 완전히 이질적인 환경(예: 급경사 위주 경로)에 대한 일반화는 여전히 제한적이다.
- 편도만 측정하므로 경사 방향이 고정된다. 왕복 측정 시 검증 가능했을 `k_slope` 비대칭(내리막 1.056배 / 오르막 0.944배)의 양방향 확인은 이번 설계에서 제외한다.

**분석 계획**: 경로별로 사람별 MAE·MAPE를 먼저 산출하고, 두 경로의 오차 패턴을 비교해 모델 편향과 경로 특성을 분리한 뒤, 전체 24개로 정속 방식 대비 통계 검정을 수행한다.

## 7. 신호대기 모델은 현 데이터로 검증 불가

신호 데이터가 커버하는 영통구 내 팀원(권동하·김재형·박준서)의 학습 경로 49개를 전수 조사한 결과, **횡단보도 반경 25m 내를 지나는 경로가 0개**였다.

| 팀원 | 경로에서 가장 가까운 신호 횡단보도까지 |
|---|---|
| 권동하 | 32 m (100m 내 4개) |
| 박준서 | 159 m |
| 김재형 | 655 m |

경사도 측정을 위해 언덕길만 선별해 걸었으므로 당연한 결과다. 따라서 **신호대기 계수의 정확도는 학습 데이터로 검증할 수 없으며**, 6절의 검증 경로 수집이 유일한 검증 수단이다.

참고로 신호대기 문서는 자체 한계로 "균등도착 가정 미검증", "타 시군 대조 시 대기를 약 +7% 과대추정" 등을 명시하고 있어, 검증 경로의 스톱워치 실측이 이 편향을 확인하는 자료가 된다.

## 8. 남은 한계 (정직하게 기재할 것)

- **검증용 독립 경로(8~10개) 미수집.** 현재 평가는 학습 데이터를 회차 단위로 분리한 홀드아웃이며, 진정한 의미의 신규 경로(아무도 걷지 않은 길, 실제 신호 포함)는 아니다. 다만 파일 단위 분리로 "처음 걷는 회차"에 대한 성능은 확보했다.
- **신호대기 검증 미완.** 엔진 연동은 완료했으나 학습 경로에 횡단보도가 없어 정확도를 확인하지 못했다(7절). 검증 경로 수집 후 스톱워치 실측과 대조해야 한다.
- 급경사 내리막(≤ −8%)의 가속을 1차식이 포착하지 못함 (속도 모델 문서에 기재된 한계 승계).
- 측정 구간의 53%가 −2~+2% 평지대에 집중되어 경사 축 변동 폭이 좁다.
- **전처리의 정지구간 감지가 1초 간격 데이터에서 작동하지 않음.** `segmentation.py`의 판정 규칙이 `step_time_s >= 3초 AND 이동 < 1m`인데, 1초 간격 기록에서는 각 스텝이 1초이므로 조건이 성립하지 않는다(60초를 서 있어도 "1초짜리 스텝 60개"로 기록됨). 실제로 134개 파일 27,208개 포인트 중 정지 판정은 **1개**뿐이었다. 이 규칙은 "사람이 멈춘 것"이 아니라 "기록이 끊긴 것"을 잡고 있다. 학습 데이터는 연속 보행이라 영향이 없었으나, **검증 데이터의 신호 대기는 GPX만으로 복원할 수 없다.** 따라서 수집 시 스톱워치 실측 기록을 필수로 요청했으며, 그 기록을 정답 삼아 순변위 기반 감지기를 튜닝할 계획이다.
- 계단은 DEM 경사도에 반영되지 않아 모델이 포착하지 못한다. 검증 경로에 계단이 포함될 경우 미모델링 오차로 남는다.

## 9. 재현 방법

```bash
python -m src.eta                              # ETA 엔진 동작 확인

# 검증 데이터 도착 후 — 최종 평가 (6절 설계)
python -m src.evaluate_validation --dem-dir data/raw/dem
python -m src.evaluate_validation --dry-run    # 데이터 도착 전 동작 확인
```

산출물: `data/processed/eval_internal.csv`, `eval_learning_curve.csv`, `validation_results.csv` (그래프용 원자료)

## 10. 검증 데이터 도착 시 실행 절차

1. GPX 24개를 `data/raw/validation/` 에 배치 (파일명 `이름_검증A_1회차.gpx` 형식)
2. 노션 기록지의 신호대기 실측을 `data/processed/validation_stopwatch.csv`로 정리

   ```csv
   person,route,trial,wait_s
   권동하,검증A,1,97
   권동하,검증A,2,55
   ```

   `wait_s` = 그 회차의 신호대기 시간 **총합**(초). 이 파일이 없으면 공공데이터
   기대대기값으로 대체 계산되며, 있으면 실측값이 우선한다.
3. `python -m src.evaluate_validation --dem-dir data/raw/dem` 실행

자동 산출되는 것:

| 출력 | 내용 |
|---|---|
| [1] 사람별 오차 | 회의 결정대로 풀링 없이 6명 각각 MAE·MAPE (경로별 분리) |
| [2] 요인별 기여도 | M0 정속 → M1 +경사 → M2 +개인화 → M3 +신호 단계별 오차 감소폭 |
| [3] 경로 간 비교 | 두 경로의 부호 오차가 일치하면 모델 편향, 갈리면 경로 특성으로 판별 |
| [4] 통계 검정 | 대응표본 t-검정 + Wilcoxon 병기 |
