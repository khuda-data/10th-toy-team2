# 모델링 인수인계 가이드

전처리 파트에서 모델링 파트로 넘기는 문서입니다. 지금까지 뭘 했는지, 결과물을 어떻게
쓰면 되는지, 그리고 의미 있는 결과를 위해 어떤 방향으로 모델링하면 좋을지 정리했습니다.
전처리 과정 자체(문제-해결 스토리)는 [전처리_진행기록.md](전처리_진행기록.md)에 더
자세히 있으니 발표 자료 준비할 때 같이 참고하세요.

## 1. 전처리에서 이미 끝난 것

1. **GPX → 좌표/시간 포인트**, GPS 튐(순간속도 15km/h 초과) 제거, 3초 이상 정지구간은
   이동시간에서 제외 (`src/segmentation.py`)
2. **고도 매핑**: 국토정보플랫폼 등고선을 TIN 보간해 자체 제작한 5m DEM으로 좌표별 고도를
   구함. 90m 공개DEM보다 계단식 아티팩트가 훨씬 적음 (`src/dem_utils.py`)
3. **30~40m 구간화**: 구간별 거리·이동시간·속도(`speed_mps`)·경사도(`slope_pct`) 산출
4. **k_slope 공통 회귀 + 개인화(v_user)**: 아래 2절 참고

**커버리지**: 6명(권동하·김재형·박준서·윤예진·최희수·홍민기), 130개 GPX 파일,
969개 구간, 전체 포인트 DEM 매핑 100%.

### 1-1. 고도 매핑, 왜 이렇게까지 했는가 (상세 과정)

모델링 팀이 `slope_pct`를 얼마나 신뢰하고 써도 되는지 판단하는 데 필요한 배경이라 자세히
남깁니다.

**문제 1 — GPX 자체 고도(`<ele>`)는 못 씀**: 스마트폰 GPS/기압고도계 오차가 커서 같은
구간을 반복 측정해도 값이 들쭉날쭉했습니다. 그래서 애초에 좌표(위도·경도)만 GPX에서
쓰고, 고도는 별도 DEM(수치표고모형)에서 가져오는 구조로 설계했습니다.

**문제 2 — 처음 쓰던 국토지리정보원 공개DEM은 90m 해상도라 30~40m 구간화와 안 맞음**:
30~40m짜리 구간 하나가 90m 픽셀 하나 안에 통째로 들어가버리면 시작/끝 고도가 같아서
경사도가 억지로 **0%**가 되고, 반대로 구간이 픽셀 경계를 넘으면 **-17%~+27%**까지
물리적으로 말이 안 되는 값이 튀었습니다("평지"로 분류된 구간에서 -3.9%/-5.2% 같은
스파이크가 나온 것도 이게 원인이었습니다).
- **진단 방법**: 홍민기\_평지\_6.gpx, 홍민기\_가파른내리막길\_1.gpx를 30m 단위로 구간화한
  뒤, 같은 구간에 대해 GPX ele / 90m DEM / 이후 만든 5m DEM 세 방식으로 경사도(%)를
  나란히 계산해서 비교했습니다. 90m 방식의 구간 간 분산이 **94.55**로 나머지 두 방식보다
  훨씬 컸습니다.

**해결 — 국토정보플랫폼 등고선을 직접 보간해서 5m DEM을 자체 제작**:
1. 상용 정밀 DEM은 비용 문제로 배제하고, 국토정보플랫폼에서 무료로 받을 수 있는
   **1:5,000 수치지형도 Ver2.0(SHP)**를 원재료로 선택
2. 한 도엽 안에 SHP 레이어가 40개 넘게 들어있어서, geopandas로 레이어마다 지오메트리
   타입·속성 컬럼을 열어보고 **등고선 레이어가 `N3L_F0010000.shp`(LineString, 고도값
   필드 `등고수치`, 구분 필드에 주곡선/계곡선)** 라는 걸 확인
3. `.prj` 파일을 직접 읽어 좌표계가 **EPSG:5186**(Korea 2000 / Central Belt 2010,
   GRS80 중부원점)임을 확인 — 참고로 기존 국토부 90m DEM은 EPSG:5179라 서로 다른
   좌표계였고, 도엽마다도 달라질 수 있어 하드코딩하지 않고 `.prj`에서 자동으로 읽게
   구현(`dem_utils.build_dem_from_contours`)
4. 등고선의 모든 정점(x, y, 고도값)을 추출해서 **Delaunay 삼각망 기반 선형보간**
   (`scipy.interpolate.LinearNDInterpolator`)으로 5m×5m 격자의 고도값을 계산. 등고선
   범위 바깥(볼록껍질 밖) 픽셀은 최근접 정점값으로 채움(`NearestNDInterpolator`)
5. GeoTIFF로 저장, rasterio로 WGS84 좌표를 자동 변환해서 픽셀값을 샘플링
   (`dem_utils.sample_dem`)
6. **검증**: 실제 GPX 좌표를 새 DEM에 넣어 고도를 뽑아보고 GPS 고도와 비교(트렌드
   일치, +2~+8m 정도의 일관된 바이어스는 GPS 고도계 오차 범위 내라 정상 판단) →
   90m 방식 대비 구간 경사도 분산이 **94.55 → 16.21(약 83% 감소)** 로 줄어드는 것 확인
7. 등고선 밀도가 낮은 구간(도엽 경계, 건물 밀집지역)에서 보간이 튀는지도 별도로
   점검(`dem_utils.detect_sparse_artifacts`) — 전체 픽셀의 0.058%만 해당, 대부분
   도엽 경계부에서 발생하는 걸로 확인해 심각한 문제는 아니라고 판단

**문제 3 — 팀원마다 측정 지역이 달라 DEM이 일부만 커버**: 92개(현재 130개) GPX
좌표의 bounding box를 계산하고 OpenStreetMap Nominatim으로 역지오코딩해서 각자
행정구역을 파악(예: 대전 중구, 수원 영통구, 용인 기흥구, 화성 동탄, 과천 등) →
국토정보플랫폼에서 지역별 등고선 도엽 9개를 받아 각각 5m DEM으로 변환 →
`build_dataset.sample_dem_df`가 여러 타일을 순서대로 시도해서 첫 유효값을 채우는
방식으로 자동 매핑. 결과적으로 전체 포인트 DEM 매핑 성공률 **100%**.

## 2. 지금 산출물이 뜻하는 것 — 이게 제일 중요합니다

경사도-속도 관계를 **두 층(layer)**으로 분리해서 만들어뒀습니다.

- **공통 층 (`k_slope_model.json`)**: "경사도가 X%일 때, 평지 대비 속도가 평균적으로 얼마나
  변하는가"를 나타내는 2차 다항식입니다. 특정 인원 데이터가 회귀를 지배하지 않도록,
  **인원별로 89개씩 균형 표본(총 534개)을 뽑아서** 적합했습니다(`sample_balanced_baseline`).
  ```
  predicted_ratio(slope_pct) = coef[0]*slope_pct**2 + coef[1]*slope_pct + coef[2]
  coef = [-0.000114, -0.005455, 0.995029]
  ```
- **개인 층 (`v_user.csv`)**: "이 사람은 평지에서 원래 얼마나 빠른가"(`v_flat_raw`)에,
  경사구간에서 보인 개인적 경향(잔차)을 Shrinkage로 보정한 값(`v_user_mps`)입니다.
  잔차는 **각자의 전체 데이터**(초과분 포함)로 계산했습니다.

**따라서 개인화된 구간 속도 예측의 기본 형태는 이렇게 결합하면 됩니다:**

```python
predicted_speed_mps = v_user_mps[person] * predicted_ratio(slope_pct)
segment_time_s = dist_m / predicted_speed_mps
```

전체 경로 ETA는 경로를 30~40m 구간으로 쪼갠 뒤(`segmentation.build_segments`와 동일한
방식) 각 구간의 `slope_pct`를 구해서 위 식으로 구간 시간을 합산하면 됩니다.

## 3. 의미 있는 결과를 위해 고려해야 할 것

### 3-1. 지금 수치가 뜻하는 한계를 반드시 인지하고 시작하세요

- `k_slope` 공통 곡선의 R²는 균형 표본에서 **0.082**, 이걸 전체 데이터(개인화 대상인
  윤예진·홍민기 초과분 포함)에 그대로 적용하면 **0.019**로 떨어집니다. 즉 "경사도만으로
  개별 구간 속도를 정확히 맞추는 모델"이 아니라, "평균적인 경향 + 개인차"를 분리해서
  보여주는 게 이 모델의 역할입니다. 모델링 단계에서 이 오차 범위(신뢰구간)를 사용자에게
  어떻게 보여줄지(예: "예상 ETA ± N분") 같이 설계하면 좋습니다.
- **지금까지 나온 R²는 전부 in-sample입니다.** 학습에 쓴 데이터로 그대로 평가한 값이라
  실제 일반화 성능이 아닙니다. **③ 검증용 데이터(전체 팀원이 나눠 담당하는 독립 경로
  8~10개, 아직 수집 전)가 들어오면 반드시 그걸로 최종 성능(MAE/RMSE, 초 단위 ETA 오차)을
  평가**해야 합니다. 이게 없으면 지금 R²로 "모델이 잘 맞는다"고 말할 수 없습니다.

### 3-2. 3단계(소량/중간/다량) 구조로 Shrinkage 효과를 "숫자로" 증명하는 방법

사람별 구간 수가 자연스럽게 3단계(baseline 4명 89~97개 / 윤예진 146개=중간 /
홍민기 454개=다량)로 갈려 있고, `shrink_w`가 0.48→0.61→0.83으로 데이터량에 비례해
커지는 것까지는 확인했습니다. 그런데 "shrink_w가 커졌다"는 것만으로는 그게 실제로
**더 나은 예측**으로 이어지는지 보여주지 못합니다. 발표에서 설득력을 가지려면 예측
오차(MAE) 숫자로 증명하는 게 좋고, 방법은 이렇게 제안합니다.

**실험 설계 (사람별 자체 hold-out)**: 각자의 구간 데이터를 train 80% / test 20%로
쪼갠 뒤(`sklearn.model_selection.train_test_split` 등), test 세트에 대해 아래 세 가지
예측 방식의 MAE(㎧ 또는 %)를 비교합니다.

| 예측 방식 | 공식 | 의미 |
|---|---|---|
| (a) 공통곡선만 (개인화 없음) | `v_flat_raw × predicted_ratio(slope)` | "다들 똑같다"고 가정 |
| (b) 현재 구조 (Shrinkage) | `v_user_mps × predicted_ratio(slope)` | 지금 파이프라인의 실제 예측 |
| (c) 순수 개인 회귀 (Shrinkage 없음) | train 세트만으로 그 사람 개인 잔차평균을 그대로 적용 | "개인화를 극단까지 밀어붙이면" |

**기대되는 패턴과 그 의미**:
- **소량 그룹(baseline 4명, n≈90 → train 72개)**: (c)가 표본이 적어 노이즈에 과적합돼서
  오히려 (a)보다 MAE가 나빠질 가능성이 높습니다. 반면 (b)는 (a)와 비슷한 수준을
  유지할 것으로 예상됩니다 — **"데이터가 적을 땐 shrinkage가 과적합을 방어해준다"**는
  근거가 됩니다.
- **다량 그룹(홍민기, n=454 → train 363개)**: (b)가 (a)보다 뚜렷하게 낮은 MAE를 보이고,
  (c)와 거의 비슷한 수준까지 근접할 것으로 예상됩니다 — **"데이터가 충분하면
  shrinkage가 자연스럽게 개인 고유값에 수렴한다"**는 근거가 됩니다.
- **중간 그룹(윤예진, n=146)**: (a)와 (c) 사이 중간 지점에 (b)가 위치할 것으로 예상됩니다.

이 세 그룹 × 세 방식 = 9개 MAE 값을 막대그래프 하나로 그리면, "왜 shrinkage가
필요하고 어떻게 작동하는지"를 말이 아니라 숫자·그래프로 보여줄 수 있습니다. 지금은
사람 내부 hold-out(20%)으로 먼저 해보고, 나중에 ③ 검증용 데이터(다른 사람이 안 걸어본
독립 경로)가 들어오면 그걸로 다시 한번 같은 실험을 재현해서 확인하는 걸 추천합니다.

### 3-3. 확장해볼 만한 방향 (우선순위 순)

1. **shrink_k(=95, 사람별 구간수 중앙값) 튜닝**: 지금은 고정값입니다. leave-one-out
   교차검증으로 여러 k값을 비교해서 예측오차가 최소가 되는 값을 찾아보면 좋습니다.
2. **2차 다항식이 최선인지 검증**: 데이터가 늘었으니 spline이나 간단한 트리 기반 모델도
   시도해볼 수 있습니다. 다만 균형 표본이 534개뿐이라 너무 복잡한 모델은 과적합 위험이
   큽니다 — 검증용 데이터로 반드시 확인하세요.
3. **개인별 slope 반응 곡선 (고급)**: 지금 `v_user`는 "베이스라인 속도"만 개인화하고,
   경사에 대한 반응 형태(k_slope 곡선 자체)는 전원 공통입니다. 홍민기처럼 데이터가
   충분한(454개) 사람에 한해 개인별 회귀를 시도해보고, 공통 곡선과 얼마나 다른지 확인해볼
   수 있습니다. 다만 나머지 인원은 표본이 적어(~90개) 개인별 회귀가 불안정할 수 있으니
   전원에 일반화하긴 아직 이릅니다.

## 4. 재현 방법

```bash
# 팀원 추가 데이터가 들어와 재전처리가 필요할 때
python -m src.build_dataset --dem-dir data/raw/dem
python -m src.model_speed --segments data/processed/segments.csv
# -> data/processed/{segments.csv, v_user.csv, k_slope_model.json} 갱신
```

`model_speed.py` 옵션: `--baseline-cap`(균형 표본 인원별 상한, 기본값=최소 구간수),
`--seed`(무작위 추출 시드), `--shrink-k`(기본값=구간수 중앙값). 모델링 실험 시 이 값들을
바꿔가며 결과가 얼마나 민감한지 확인해보는 것도 좋습니다.
