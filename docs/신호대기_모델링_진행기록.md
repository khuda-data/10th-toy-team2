# 신호대기 모델링 — 영통구 횡단보도별 기대대기 산출

> 2026-08-21 · 박준서
> 입력: 행안부 표준데이터 2종 (data.go.kr)
> 수신: 평가·검증 담당, ETA 조립 담당

기획안 「B. 신호대기」의 수학식을 공공데이터에 적용해 영통구 횡단보도 351개의
기대 신호대기시간을 산출했습니다. **실측·검증 걷기 데이터는 쓰지 않았습니다.**

**ETA 조립 담당자는 1절만 보셔도 됩니다.**

## 1. 최종 산출물 — 어느 파일을 쓸 것인가

| 용도 | 파일 | 비고 |
|---|---|---|
| **경로 ETA (최종)** | `data/processed/영통구_횡단보도별_신호대기.csv` | 횡단보도 351개, 개별 `기대대기_s` |
| **경로 연결 도구** | `src/route_wait.py` | 좌표·GPX → 관리번호 → 대기 합 |
| **지도** | `data/processed/영통구_횡단보도.geojson` | GitHub 에서 클릭하면 지도로 보임 |
| **차로수별 요약** | `data/processed/영통구_차로수별_대기요약.csv` | 매칭 안 되는 경우의 대체값 |
| **코드 연동용** | `models/yeongtong_signal_params.json` | `signal_wait.load_region_params()` |

### 경로 ETA 계산식

```python
개인 맞춤 ETA = Σ(구간거리 ÷ (v_user × k_slope)) + Σ(신호대기)
```

신호대기 항은 **경로가 지나는 횡단보도를 위 CSV 에서 찾아 `기대대기_s` 를 합산**합니다.

### 경로에 붙이는 법 — `route_wait.py`

검증 걷기 데이터에는 `횡단보도관리번호` 가 없습니다. 주소도 351개 중 147개(42%)가
결측이라 키로 못 씁니다. **좌표가 유일하게 100% 채워진 연결 키**입니다.
이걸 잇는 것이 `src/route_wait.py` 입니다.

```bash
# ① 좌표 → 관리번호   걸으면서 찍은 위치에 ID 붙이기
python src/route_wait.py --at 37.25033 127.07931

# ② 관리번호 → 대기 합   ETA 에 넣을 값
python src/route_wait.py --ids 수원-1965 수원-1951 수원-0306
#   → 신호대기 합 165.4초 (± 75.2초)

# ③ GPX → 건넌 횡단보도 자동 판정
python src/route_wait.py --gpx data/raw/박준서_평지_1회차.gpx
```

①은 후보를 여러 개 보여주고 **사람이 고르게** 합니다. 교차로에는 횡단보도가
3~4개 붙어 있어 자동으로 하나만 고르면 틀립니다. 완전 자동화는 일부러 안 했습니다.

②는 표준편차도 같이 냅니다. 신호대기는 표준편차가 평균에 육박하므로
(0초 아니면 100초) 기대값만 내면 ETA 가 실제보다 정확해 보입니다.

```python
import route_wait as rw
cw = rw.load()
rw.summarize(rw.wait_of(cw, ['수원-1965', '수원-1951']))
# {'횡단보도': 2, '신호': 2, '기대대기_s': 110.6, '표준편차_s': 59.4}
```

#### ⚠️ 단순 반경으로 매칭하면 안 됩니다

③의 통과 판정에 **고정 반경을 쓰면 건너지도 않은 횡단보도의 대기가 붙습니다.**
실측으로 확인했습니다.

```
권동하_평지_1회차.gpx   274m 를 196초에 걸음 (평균 1.40 m/s, 정지 2초)

  반경 30m → 횡단보도 0개
  반경 40m → 3개 (신호 2개), 대기 110.6초    ← 유령
```

110.6초가 진짜라면 순보행이 85초, 즉 3.21 m/s(시속 11.6km)라 불가능합니다.
가장 가까운 횡단보도를 보면 이유가 나옵니다.

| 관리번호 | 트랙까지 | 횡단거리 | 기대대기 |
|---|---|---|---|
| 수원-1965 | 31.9m | 12.6m | 42.0초 |
| 수원-1951 | 33.0m | 15.8m | 68.6초 |

**횡단거리 12.6m 를 실제로 건넜다면 트랙이 중심에서 6m 안을 지나야 합니다.**
31.9m 는 건너지 않고 옆을 스쳐 간 것입니다.

그래서 각 횡단보도의 **자기 길이**를 기준으로 잡습니다.

```
임계값 = max(횡단거리 ÷ 2, 5m) + GPS 오차 10m
```

회귀 시험으로 확인했습니다.

| 시험 | 기대 | 결과 |
|---|---|---|
| 횡단보도를 가로지르는 인공 트랙 | 검출 | 1개 ✅ |
| 20m 옆으로 비껴가는 트랙 | 미검출 | 0개 ✅ |
| 영통구 실측 GPX 53개 | — | 0개 (경사도 실험 경로라 횡단보도 없음, 최근접 31.9m) |

횡단보도를 특정할 수 없을 때만 차로수별 평균을 쓰세요.

```python
import json
p = json.load(open('models/yeongtong_signal_params.json', encoding='utf-8'))
p['wait_by_lane_bin']    # {'3차로 이하': 42.5, '4~5차로': 54.1, '6차로 이상': 54.1}
```

> ⚠️ **전체 평균(53.7초)을 경로 계산에 쓰지 마세요.**
> 이 값은 영통구 횡단보도를 균등하게 뽑았을 때의 평균입니다. 보행자는 이면도로
> 횡단보도는 피해 갈 수 있어도 간선도로는 반드시 건너므로, 실제 경험하는 대기는
> 이보다 큽니다. 경로에 실제로 있는 횡단보도를 써야 합니다.

## 3. 적용한 수학식 (기획안 그대로)

```
보행 녹색   G = 진입 7초 + 횡단거리 ÷ 1.0 m/s      (경찰청 교통신호기 설치·관리 매뉴얼)
보행 적색   R = C − G
기대 대기   E[W] = R² / (2C)                       (기획안 B절)
```

`E[W] = R²/(2C)` 는 보행자가 주기 안 임의 시점에 도착한다는 **균등도착 가정**에서
나온 값입니다. 실측 데이터가 없어 이번 산출에서는 **이 가정을 검증하지 않고 그대로
적용**했고, 따라서 분산·신뢰구간은 내지 않고 기대값만 냈습니다.

`G` 가 주기의 60% 를 넘으면 상한으로 잘랐습니다(현실에 없는 신호). 2개 적용됐습니다.

## 4. 주기 C 를 어떻게 구했나 — 데이터를 바꿔야 했던 이유

### 문제: 수원시가 신호시간을 제출하지 않았음

「전국횡단보도표준데이터」에는 `녹색신호시간`·`적색신호시간` 컬럼이 있습니다.
그런데 **영통구 300개 전부 결측**이었습니다.

```
녹색신호시간   신호등有 300개 중 채워짐 0개   (결측률 100%)
적색신호시간   신호등有 300개 중 채워짐 0개   (결측률 100%)
```

이 표준데이터는 지자체가 직접 등록하는 방식이라 항목별 제출 여부가 갈립니다.
같은 경기도라도 의정부시·구리시·포천시는 100% 제출, 수원시는 0% 입니다.

### 해결: 신호등 표준데이터의 `신호등화시간`

「전국신호등표준데이터」에 다른 형태로 들어 있었습니다.

```
신호등화순서 : 녹색 + 황색 + 적색
신호등화시간 : 36 + 3 + 111        →  합 150초 = 주기 C
```

**영통구 379개 전부 채워져 있습니다.**

이 데이터는 전부 차량신호등(`신호등구분 = 1`)입니다. 그래도 쓸 수 있는 이유는,
**한 교차로의 모든 방향이 같은 주기로 돌기 때문**입니다. 방향마다 다른 것은
녹색 배분이지 주기가 아닙니다. 우리가 필요한 건 `C` 하나입니다.

### 처리 순서

| 단계 | 결과 |
|---|---|
| 영통구 추출 | 횡단보도 351개 · 신호등 379개 |
| 점멸등 제외 (`황색` 단독, C=0) | −40개 |
| 주기 결측·범위밖(40~300초) 제외 | −5개 → 유효 334개 |
| 교차로 군집화 (반경 40m) | 267곳 (신호주 평균 1.3개/교차로) |
| 횡단보도 ↔ 교차로 공간결합 ①근접 75m | 162개 (결합거리 중앙 25m) |
| 　　　　　　　　　　　　②동일노선 150m | +52개 (결합거리 중앙 120m) |
| 　　　　　　　　　　　　합계 | **214/300개 매칭 (71%)** |
| 미매칭 86개 보정 | 영통구 **자체** 차로수별 중앙값 |

교차로로 묶은 이유: 묶지 않으면 신호주가 많은 대형 교차로가 통계를 지배합니다.

미매칭분에 전국 표준값이 아니라 영통구 자체 중앙값을 쓴 것이 중요합니다.
같은 동네에서 뽑았으므로 가정의 폭이 훨씬 작습니다.

### 5-1. 파싱 검증 — `신호등화시간` 이 정말 전체 주기인가

`신호등화시간` 의 항목 수와 `신호등화순서` 의 위상 수를 교차표로 비교했습니다.

| **3** | 167 | 0 | 0 | 0 | 0 |
| **4** | 0 | 30 | 0 | 0 | 0 |
| **5** | 0 | 0 | 127 | 0 | 0 |

**334개 전부 대각선에 놓입니다.** 시간 항목이 위상과 1:1 대응하므로 합이 전체 주기입니다.

### 5-2. 규정식 `G = 7 + L/1.0` 검증 (외부 정답 대조)

수원시는 녹색신호시간을 제출하지 않았지만, 경기도 다른 시군(의정부·구리·포천·
남양주·파주·이천·양주)은 제출했습니다. **실측 2,779개**에 규정식을 대보았습니다.

| 횡단거리 | n | 실측 녹색(중앙) | 규정식 | 편향 | MAE |
|---|---|---|---|---|---|
| ~10m | 577 | 16.0초 | 15.2초 | −2.7초 | 3.1초 |
| 10–15m | 786 | 20.0초 | 20.0초 | −1.7초 | 2.8초 |
| 15–20m | 605 | 24.0초 | 24.5초 | −0.1초 | 2.2초 |
| 20–25m | 458 | 29.0초 | 29.3초 | +0.9초 | 2.3초 |
| 25–30m | 254 | 34.0초 | 34.5초 | +0.8초 | 2.4초 |
| 30m+ | 99 | 38.0초 | 39.3초 | +2.0초 | 2.8초 |
| **전체** | **2,779** | | | **−0.8초** | **2.6초** |

**규정식이 실제 운영을 잘 맞춥니다.** 전 구간에서 편향이 ±3초 이내이고,
영통구 중앙값 구간(25~30m)에서는 +0.8초입니다.
`∂E[W]/∂G = −R/C ≈ −0.78` 이므로 이 오차가 대기에 주는 영향은 약 0.6초(1%)입니다.

> 회귀선 자체(`녹색 = 11.16 + 0.795 × 연장`)는 규정식(`7 + 1.0 × 연장`)과 다릅니다.
> 두 계수가 서로 상쇄되어 관측 범위 안에서 예측값이 거의 일치하는 것이므로,
> 계수를 비교하지 말고 예측 오차를 보아야 합니다.

### 5-3. 방법 전체 정답 대조 — 다른 도시에서 검증

우리 방법(신호등 데이터 → 교차로 군집 → 공간결합)이 옳은지 확인하려면,
'정답 주기'를 아는 도시에서 돌려보면 됩니다. 횡단보도 데이터에 신호시간을
제출한 세 도시에 **동일한 코드를 그대로 적용**했습니다.

| 도시 | 대조 n | 정답 주기 | 우리 추정 | 주기 편향 | **대기 편향** | 대기 MAE | 상관 |
|---|---|---|---|---|---|---|---|
| 의정부시 | 345 | 124.3초 | 130.3초 | +6.1초 | **+2.9초 (+7.1%)** | 8.7초 | 0.570 |
| 구리시 | 213 | 120.8초 | 126.4초 | +5.6초 | **+2.7초 (+6.8%)** | 5.4초 | 0.787 |
| 포천시 | 32 | 130.0초 | 129.2초 | −0.8초 | **−0.4초 (−0.9%)** | 0.4초 | 0.999 |

**두 도시에서 +7% 안팎, 한 도시에서 −0.9%** 입니다.
이 방법은 대기를 약 7% 과대추정하는 경향이 있습니다.
영통구 53.7초를 보정하면 약 50초입니다.

다만 두 가지를 구분해야 합니다.

- **집계(경로) 수준은 신뢰할 만합니다** — 편향 3초 이내
- **개별 횡단보도는 부정확합니다** — MAE 5~9초

경로 ETA 는 여러 횡단보도의 합이라 개별 오차가 상당히 상쇄되지만,
"이 횡단보도에서 몇 초 기다린다"는 식의 개별 예측에는 쓰지 마세요.

이 검증은 부수적으로 **영통구 주기가 긴 것이 방법의 편향이 아님**도 보여줍니다.
영통 주기는 경기도 타 시군보다 16~38초 긴데 방법 편향은 6초뿐이므로,
나머지는 실제 차이입니다(수원시가 훨씬 큰 도시).

| 100m | 75% | 170초 | 53.4초 |
| 125m | 78% | 180초 | 53.6초 |
| 150m | 81% | 171초 | 53.2초 |

**매칭률이 66%→81% 로 변하는데 평균 기대대기는 0.7초 안에서 움직입니다.**
결합 반경 선택에 결과가 좌우되지 않습니다.
(도로명 매칭 도입 전에는 이 폭이 1.5초였습니다 — 더 안정해졌습니다.)

### 5-5. 도로명 매칭 — 커버리지를 어떻게 늘렸나

좌표만으로는 보행신호 300개 중 162개(54%)에만 주기를 붙일 수 있었습니다.
나머지는 차로수별 중앙값이라는 거친 대체값을 썼습니다.

두 데이터셋 모두 도로명이 있습니다(횡단보도 `도로명`, 신호등 `도로노선명`).
영통구 횡단보도 도로명 36종 중 **32종이 신호등 데이터에도** 있습니다.

**근거** — 같은 노선의 신호는 연동제어로 주기를 공유합니다. 실제로 노선명이
주기 분산을 설명하는 비율은 영통 44%, 의정부 37%, 구리 48% 입니다.

#### 시행착오 두 가지 (둘 다 데이터가 뒤집었습니다)

**① `~번길` 을 떼어 상위 도로로 묶으면 안 됩니다.**

| | 영통 | 의정부 | 구리 |
|---|---|---|---|
| 노선명 그대로 | **44%** | **37%** | **48%** |
| 번길 제거 | 19% | 30% | 29% |

간선(`광교로`)과 그 이면도로(`광교로42번길`)는 주기가 실제로 다릅니다.
매칭을 늘리려고 묶으면 오히려 정보가 사라집니다. 정확 일치만 씁니다.

**② 도로명을 1순위에 두면 정확도가 나빠집니다.**

처음에는 "도로명이 같으면 우선"으로 짰는데, 정답 대조에서 의정부 공통
매칭분 MAE 가 18.1 → 18.2초, 상관이 0.562 → 0.512 로 악화했습니다.
더 가까운 다른 도로 교차로를 밀어내고 **더 먼 같은 도로 교차로**를
고르기 때문입니다.

그래서 순서를 뒤집었습니다.

```
1순위  반경 75m 안 최근접 교차로 (도로명 무관)
2순위  1순위가 없을 때만, 도로명이 같은 교차로를 150m 까지
```

기존 매칭을 건드리지 않고 못 찾은 것만 줍는 구조라 **정확도 악화가
구조적으로 불가능**합니다. 정답 대조에서 공통 매칭분 MAE 가 모든 반경에서
동일하게 유지되는 것으로 확인했습니다(의정부 18.1초, 구리 11.4초).

#### 확장 반경을 150m 로 정한 근거

정답을 아는 의정부에서, **새로 매칭된 횡단보도**의 주기 오차를
그것이 원래 받았을 대체값과 비교했습니다.

| 확장 반경 | 신규 매칭 | 신규 MAE | 대체값 MAE | 판정 |
|---|---|---|---|---|
| 125m | 5개 | 27.6초 | 38.0초 | 개선 |
| **150m** | **11개** | **19.6초** | **42.9초** | **채택** |
| 200m | 28개 | 36.9초 | 42.9초 | 개선폭 급감 |

200m 는 커버리지는 늘지만 먼 교차로를 끌어와 정확도가 떨어집니다.

#### 결과

| | 도입 전 | 도입 후 |
|---|---|---|
| 실측 주기 확보 | 162/300 (54%) | **214/300 (71%)** |
| 대체값 의존 | 138개 | **86개** |
| 평균 기대대기 | 54.7초 | 53.7초 |
| 반경 민감도 폭 | 1.5초 | **0.7초** |
| 정답 대조 상관 (의정부) | 0.562 | **0.570** |

집계 평균은 1초밖에 안 움직입니다. 대체값(6차로 180초)이 실측 주기와
자주 일치했기 때문입니다. 실질적 개선은 개별 횡단보도에 있습니다.

```
값이 바뀐 횡단보도   24개 (8%)
  변화폭 절대 평균   15.4초
  최대 변화         51.7초
```

경로 ETA 는 특정 횡단보도를 지목해 합산하므로, 이 24개 중 하나가 검증
경로에 포함되면 집계 평균이 시사하는 것보다 훨씬 큰 차이가 납니다.

## 7. 한계 (보고서 필수 기재)

방향까지 함께 적습니다. 과대·과소 요인이 섞여 있어 부호가 중요합니다.

| # | 한계 | 대기에 미치는 방향 | 크기 |
|---|---|---|---|
| 1 | 방법 자체의 과대추정 (5-3) | **과대** | 약 +7% |
| 2 | 교통섬 46개(15%)의 2단 횡단을 1회로 계산 | **과소** | 미측정 |
| 3 | 보행 녹색 `G` 가 규정식 추정값 | 과대 | 약 +1% (5-2) |
| 4 | 균등도착 가정 미검증 | 불명 | 불명 |
| 5 | 버튼식 여부 미상 | 불명 | 불명 |
| 6 | 시간대별 주기 변동 미반영 | 불명 | 불명 |

1번과 2번은 **방향이 반대라 일부 상쇄**됩니다. 순 효과는 검증 걷기로만 알 수 있습니다.

- **방법이 대기를 약 +7% 과대추정합니다** (5-3, 정답 대조). 개별 횡단보도 오차는
  MAE 5~9초로 큽니다. 집계 수준에서만 쓰세요.
- **교통섬이 있는 신호 횡단보도가 46개(15%)** 입니다. 2단 횡단이면 대기가 두 번
  생길 수 있는데 모델은 1회로 계산합니다. 과소추정 요인입니다.
  (`횡단보도종류 = 04` 인 49개 중 38개가 교통섬 보유 — 중앙섬형으로 추정)
- **보행 녹색시간 `G` 는 실측이 아니라 규정식 추정값입니다.** 다만 5-2 에서
  경기도 실측 2,779개와 대조해 편향 −0.8초(MAE 2.6초)임을 확인했습니다.
  영향은 대기의 약 1% 로 작습니다.
- **균등도착 가정은 검증하지 않았습니다.** 실측 대기 데이터가 없기 때문입니다.
  검증하려면 검증 걷기에서 횡단보도별 대기 시간을 기록해야 합니다
  (기다리지 않은 경우 0 을 기록하는 것이 특히 중요합니다).
- **버튼식 여부는 미상입니다 — 0개가 아닙니다.** 표준데이터의
  `보행자작동신호기유무` 칸이 영통구 351개 전부 공백입니다. 버튼식이 섞여 있으면
  그 지점은 균등도착이 성립하지 않습니다.
- 미매칭 86개(29%)는 영통구 차로수별 중앙값으로 채웠습니다. 개별 값은 부정확할 수
  있으나, 5-4 의 민감도 분석이 집계 수준에서는 영향이 작음을 보여줍니다.
  (도로명 매칭 도입 전에는 138개(46%)였습니다 — 5-5 참조)
- `3차로 이하` 구간은 보행신호 있는 횡단보도가 **10개뿐**이고 그중 매칭은 9개입니다.
  이 구간의 42.5초는 표본이 얇으니 단독 인용하지 마세요.
- 시간대별 신호 운영(출퇴근 시간대 주기 연장)은 반영하지 않았습니다.
  표준데이터에 해당 정보가 없습니다.
- 무신호 횡단보도 51개는 대기 0 으로 처리했습니다. 실제로는 차량 간격을 기다리는
  지체가 있으나 기획안 수식의 범위 밖입니다.
- 표준데이터 갱신주기가 반기입니다. 기준일자는 횡단보도 2026-05-13,
  신호등 2026-05-28 이라 최근 신호 개선은 미반영일 수 있습니다.

## 8. 다음 담당자에게

**검증 걷기에서 이것만 기록해 주시면 균등도착 가정을 검증할 수 있습니다.**

| 기록할 것 | 왜 |
|---|---|
| 횡단보도별 대기 시간(초) | 이론값과 비교 |
| **기다리지 않았으면 0** | 빠뜨리면 평균이 부풀려져 검증이 통째로 틀어짐 |
| 경로별 대기 시간 합계 | 총 ETA 에서 빼면 신호 가정과 무관한 보행 전용 비교 가능 |
| 건넌 지점의 좌표(또는 사진) | `route_wait.py --at` 로 관리번호를 붙일 수 있음 |

경로를 짜기 전에 `data/processed/영통구_횡단보도.geojson` 을 GitHub 에서 열어
보세요. 지도로 렌더됩니다. 신호 있는 횡단보도가 빨강 300개, 없는 것이 파랑 51개입니다.

**횡단보도 밀도를 경로마다 다르게 잡아 주세요.** 4km/h 베이스라인은 우리 전원보다
느려서, 그 느슨함이 신호대기를 우연히 상쇄합니다. 손익분기 밀도는 개인별로
2.4~5.3개/km 이고, 그 근처에서만 걸으면 "우리 모델 = 지도앱" 이라는 결과가 나옵니다.
횡단보도 0~1개 경로와 5개+ 경로를 함께 넣어야 두 항의 기여가 분리됩니다.

검정 방법은 두 가지를 권합니다.

1. **무대기 비율 검정** — 균등도착이면 대기 0 인 비율이 녹색 비율 `G/C` 와 같아야
   합니다. 평균 비교보다 날카롭습니다.
2. **비율 보정 λ = Σ실측 / Σ이론** — 회귀 `실측 = α + β×이론` 의 β 보다 정밀합니다.
   (β 는 지점 간 이론값 차이가 작아 현실적 표본으로는 신뢰구간이 좁혀지지 않습니다.)
