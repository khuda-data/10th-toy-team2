# 신호대기 모델 → 최종 ETA — `evaluate_validation.py` 와 무엇이 다른가

작성 2026-08-24 · 박준서 · 재현 `python -m src.evaluate_signal_eta`

저장소에 **ETA 평가 스크립트가 두 개** 생겼다. 헷갈리기 쉬우니 먼저 차이부터
적는다. 둘 다 필요하고, 둘 중 하나가 틀린 것이 아니다.

---

## 1. 한 줄 차이

| | `evaluate_validation.py` (권동하) | `evaluate_signal_eta.py` (박준서) |
|---|---|---|
| 신호대기 항 | **스톱워치 실측을 그대로 더함** | **GPX 좌표 → 표준데이터 매칭 → E[W]** |
| 답하는 질문 | 신호를 완벽히 알면 얼마나 되나 | 공개데이터만으로 서비스하면 얼마나 되나 |
| 성격 | 오라클(상한) | 실제 예측 |
| 정방향 12회 최고 성적 | MAE 27.8초 / 2.9% | MAE 45.9초 / 4.5% |

`validation_results.csv` 에서 이것이 기계적으로 확인된다.

```
M3_신호 − M2_개인화  ==  신호대기_실측      →  16/16 성립 (부동소수 오차 1e-13)
```

즉 `actual_s = 도보실측 + 신호실측` 인데 `M3 = 도보예측 + 신호실측` 이라
빼면 신호 항이 **정확히 상쇄된다. M3 의 오차는 도보 항의 오차와 같다** —
신호 항이 기여하는 오차가 정의상 0 이다. 실측 대기는 정답의 평균 **18%**
(회차별 8~25%)를 차지한다.

권동하 커밋도 이 점을 숨기지 않았다("신호는 스톱워치 실측", "실서비스
조건에서는 MAE가 84초가 아니라 99초"). **오라클 실험으로는 타당한 설계다.**
문제는 그 수치가 대표값으로 발표될 때 생긴다.

**발표에는 세 줄을 같이 넣자.**

```
신호를 못 세면              20%↓   (기존 검출기)
공개데이터로 예측하면        69%↓   ← 실서비스 조건
신호 정답을 알면            81%↓   (상한)
```

오라클과의 18초 차이는 대부분 줄일 수 없다. 경로별 실측평균을 정확히 알아도
신호 항 MAE 가 35.8초다(도착시각에 대한 신호 위상이 랜덤이라 생기는 몫).
이 모델은 38.8초로 그 하한에 3초까지 붙어 있다.

### 주의 — M4 의 `v_user` 재추정은 누수가 아니다

`v_LOO` 는 **그 회차를 빼고** 같은 사람의 나머지 회차로 추정한 값이다.
"이력이 있는 재방문 사용자"를 모사한 것으로 정당하다. 문제가 되는 것은
M3·M4 에 섞인 **신호 항**뿐이다.

## 3. 신호대기 모델을 무엇으로 고쳤나

### 3-1. 출발점의 문제

검증 걷기로 확정한 신호 횡단보도는 **9곳**이다(경로 A 4곳, B 5곳).
4명 16회차 전원이 이 9곳을 최대 6.8m 이내로 통과했고, 목록 밖에서 멈춘
기록은 정지 58건 중 0건이다.

기존 영통구 검출기는 이 9곳 중 **회차당 1~2곳**만 잡았다. 원인은 두 가지.

1. **9곳 중 3곳이 횡단보도 표준데이터에 아예 없다** (A-1·A-2·B-1).
2. **좌표가 보행로에서 체계적으로 어긋나 있다.** 실제로 건넌 것이 확인된
   횡단보도까지 트랙 거리가 3.9 / 19.3 / 22.8 / 30.5 / 44.2m 다.
   임계값 20m 로는 대부분 탈락한다.

### 3-2. 고친 것 세 가지

| | 이전 | 이번 |
|---|---|---|
| 후보 범위 | 영통구 351개 | 수원시 2,064개 |
| 결측 보충 | 없음 | 신호등만 있는 교차로 453개 → **가상 횡단보도** |
| 좌표 여유 / 임계상한 / 교차로 | 10 / 20 / 80m | **30 / 35 / 60m** |
| 보정계수 λ | 없음 | **0.745** |

**가상 횡단보도** — 횡단보도 행이 없어도 그 자리에 신호등 행이 있으면
주기 C 를 알 수 있고, 그러면 `G = 7 + L/1.0`, `R = C − G`, `E[W] = R²/(2C)`
가 계산된다. 횡단거리는 수원시 신호 횡단보도 중앙값(17.9m)을 쓴다.
A-1·A-2 는 신호등 599(수원시 영통구 덕영대로 1689, C=180초),
B-1 은 신호등 1336(영통동 995-5, C=140초)으로 메워졌다.

**좌표 여유 30m** 는 GPS 가 나빠서가 아니다. 지배 요인은 **표준데이터
좌표의 등록 오차**이고, 상수 주석도 그렇게 고쳤다.

### 3-3. 어느 것이 효과였나 (LOPO MAE, 16회차)

| 구성 | 후보수 | λ | MAE |
|---|---|---|---|
| ① 영통구 원본 + 기존 파라미터 (출발점) | 351 | 1.80 | 71.8 |
| ② 영통구 원본 + **새 파라미터** | 351 | 0.84 | **43.6** |
| ③ ② + **신호등 보충** | 518 | 0.73 | **36.1** |
| ④ ③ + **수원시 확대** (채택) | 2,517 | 0.74 | **35.9** |
| ⑤ 수원시 + 보충 + 기존 파라미터 | 2,517 | 1.57 | 96.7 |

**개선의 대부분은 파라미터 재조정(28.2초)과 신호등 보충(7.5초)에서 나왔다.
수원시 확대 자체는 0.25초로 사실상 기여가 없다.** 두 검증 경로를 감싸는
좌표 상자 안에서는 영통구 추출본과 수원시 추출본의 횡단보도 집합이 완전히
같기 때문이다(각 41개, 차집합 공집합).

수원시 확대는 그래도 유지한다 — 경로가 구 경계를 넘을 때를 위한 것이고,
⑤ 가 보여주듯 파라미터 없이 범위만 넓히면 오히려 나빠진다.

## 5. 남은 문제 — 이제 병목은 도보시간이다

16회차 기준

| 항목 | MAE | 편향 | MAPE |
|---|---|---|---|
| 신호대기 — 보정 | 38.8 | −8.9 | 26.0% |
| **도보시간** | **85.7** | **+52.7** | 11.7% |
| 최종 ETA (콜드스타트) | 93.6 | +44.1 | 10.0% |

```
도보를 정답으로 고정 → 신호 항만    MAE  38.8초   (오라클 하한 35.8초)
신호를 무시 → 도보 항만            MAE 125.4초   편향 −123.4초
```

**신호 항은 한계까지 갔다.** 전체 편향 +44.1초는 사실상 도보 항이 혼자
만든다. 권동하 커밋의 진단(v_user 도메인 시프트, 경사 실험용 반복 보행이
목적지 지향 연속 보행보다 최대 21% 느림)과 같은 결론이다.

| person | ETA MAE | 도보 편향 | 신호 편향 | 실측 순보행속도 | v_user(학습) |
|---|---|---|---|---|---|
| 권동하 | 84 (7.7%) | **−66** | −18 | 1.261 | 1.360 |
| 박준서 | 135 (15.7%) | **+141** | −6 | 1.573 | 1.301 |
| 최희수 | 71 (8.5%) | **+83** | −13 | 1.838 | 1.627 |
| 홍민기 | 84 (8.0%) | **+52** | +2 | 1.409 | 1.332 |

신호 편향은 네 사람 모두 −18~+2초로 작다. 도보 편향은 −66~+141초다.

## 6. 한계

1. **교차로 안에서 어느 다리를 건넜는지 못 가른다** (배정거리 최대 118m).
2. **경로 B 초과검출 7건** — 건너지 않은 횡단보도가 회차당 0~2개 붙는다.
3. **수원-1968(B-5) 의 `보행자신호등유무=N` 오기재를 안 고쳤다.** 실측
   평균 44.2초(최대 106초)인데 이론이 0 이다. 고쳐봤더니 λ 가 흔들려
   전체가 **나빠졌다**(LOPO 35.8 → 38.1초) — λ 가 다른 지점의 과대추정을
   상쇄하고 있었기 때문이다. 근본 해결은 지점별 보정이고 표본이 부족하다.
4. **용인시는 못 메운다.** 행안부 표준데이터에 용인시 행이 전국을 통틀어
   0건이다(경기도 31개 시군 중 15개 미제출). 덕영대로는 1689 번지까지만
   데이터가 있고, 경희대 국제캠퍼스 정문 방향은 공백이다.
5. **가상 횡단보도의 횡단거리는 전부 중앙값(17.9m) 가정** — 짧은 횡단보도
   에서 과대추정한다(A-2 +25초, B-1 +17초).
6. **λ = 0.745 는 경로 2개·사람 4명에서 나왔다.** 부트스트랩 95% CI
   [0.685, 0.877]. LOPO(3명으로 추정 → 남은 1명 적용) MAE 35.9초,
   편향 +0.2초로 과적합은 아니지만 **다른 지역에 그대로 쓰면 안 된다.**
7. `eta.py` 는 GPX 원본이 아니라 **40m 구간 폴리라인**으로 통과 판정을
   한다. 기하가 성기어져 같은 λ 에서 MAE 가 35.9 → 38.8초로 벌어진다.
