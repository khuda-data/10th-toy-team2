# 검증 단계 회의 결정 사항

> 2026-08-22 팀 회의 · 정리: 홍민기(전처리) + Claude
> 대상: 모델링(k_slope v2 / v_user v2), 신호대기 모델, 검증 데이터 수집 계획

회의에서 결정된 6개 항목을 그대로 옮기고, 각 항목이 실제 코드·데이터로 확인되는지
검토한 뒤 근거를 붙였습니다. 검증 데이터가 들어오기 전 미리 합의해둬야 할 것들이라
잊지 않도록 문서로 남깁니다.

---

## 1. 변경된 모델 설명 (속도 모델, 신호대기 모델)

두 모델 다 v1 대비 크게 바뀌었고, 상세 내용은 각 진행기록 문서에 있습니다.

- 속도 모델: [모델링_진행기록.md](모델링_진행기록.md) — 종속변수를 `speed_ratio`(정규화)로,
  차수를 2차→1차로, in-sample R²만 보던 걸 사람 단위 교차검증(GroupKFold)으로 바꿈
- 신호대기 모델: [신호대기_모델링_진행기록.md](신호대기_모델링_진행기록.md) — 가정치(적색
  80초/주기 120초)를 행안부 공공데이터 실측치(주기 130~180초)로 교체, 타 시군 정답 대조로
  방법 자체의 편향(+7% 과대추정)까지 검증

**요약**: 개인차(25.7%)가 경사 효과(10% 경사에서 5.6%)보다 약 4.5배 크다는 게 속도 모델의
핵심 결론이고, 신호대기는 기존 가정보다 실제로 28.4% 더 길다는 게 핵심 결론입니다.

## 2. 검증 결과는 6명 각각 산출

풀링하지 않고 사람별로 따로 낸다. **근거**: 이 프로젝트의 메인 메시지가 "개인차가 크다"인데
검증 결과를 풀링해서 평균 하나로 내면 그 메시지 자체를 검증할 수 없음. 6명 각자의 예측
ETA vs 실제 소요시간 오차를 따로 봐야 "개인화가 실제로 맞았는지"를 사람별로 확인 가능.

## 3. 신호대기 + 개인화 속도를 더하면 네이버맵과 비슷한 결과가 나올 수 있음

**검토 결과**: 타당한 예상이고, 이번엔 우려할 신호가 아니라고 판단합니다.

이전 세션에서 "슬로프 개인화만으로 네이버맵에 가까워지면 개인화가 무의미해지는 것 아니냐"는
논의가 있었는데, 그건 **개인화 신호 하나만 봤을 때** 얘기였습니다. 여기에 신호대기(실제
인프라 요소)까지 더하면 상황이 다릅니다 — 실제 인프라 요소를 전부 반영하면, **평균적인
사람 기준으로는** 네이버 같은 상용 지도와 비슷한 범위로 수렴하는 게 자연스럽습니다(둘 다
같은 물리적 현실 — 거리, 신호, 경사 — 을 예측하려는 것이므로).

**진짜 봐야 할 지점**: 평균적인 사람은 네이버와 비슷하게 나오되, 원래 평균과 다르게 걷는
사람(예: 최희수 — 팀 평균 대비 +18.3%, 김재형 — −5.9%)은 네이버 추정치와 **얼마나 벌어지는지**
가 우리 모델의 차별점입니다. 이 벌어지는 정도를 발표에서 강조하는 걸 추천합니다.

## 4. 표본이 적어 Shrinkage를 쓰면 개인 ETA의 의미가 옅어질 수 있음 (⇒ v_user v2는 Shrinkage 미적용, 의도된 결정으로 확정)

**검토 결과**: 설득력 있는 논리로, 실제 숫자로도 확인됩니다.

`shrink_k≈95`(구간수 중앙값) 기준으로 baseline 4명(권동하·박준서·최희수·김재형, n≈89~97)의
`shrink_w`를 계산하면 **0.48~0.51** — 즉 이 4명은 개인값의 절반 가까이가 팀 평균 쪽으로
당겨집니다. "6명 각자의 개인차를 선명하게 보여준다"는 지금 발표 목적에는 이 절반 손실이
맞지 않는다는 게 이번 결정의 근거입니다.

v2의 `v_user`가 Shrinkage 없이 순수 평균(`mean(speed_mps ÷ k_slope(slope_pct))`)으로
계산된 것은 이 결정과 일치합니다(직접 재계산해서 `v_user_v2.csv`와 일치 확인 완료).

**단서 하나 남겨둠**: 이건 "지금 이 6명을 보여주는 발표"에는 맞는 선택이지만, 향후
서비스가 커져서 데이터가 거의 없는 신규 사용자(구간 0~5개)가 들어오는 상황을 가정하면
Shrinkage 없이는 그 사람 몇 개 안 되는 데이터만으로 극단값이 나올 위험이 있습니다.
**"지금은 6명 모두 충분한 표본(89개 이상)이라 Shrinkage가 불필요했지만, 사용자 수가
늘어나 표본이 작은 신규 사용자가 생기면 재도입을 고려해야 한다"**는 점을 한계로 같이
기재해두면, 질의응답에서 관련 질문이 나왔을 때 바로 답할 수 있습니다.

## 5. 검증용 데이터는 같은 구간으로 산출

전원이 동일 경로를 걸어서 검증 데이터를 만든다. **근거**: 사람마다 다른 경로로 검증하면
"오차가 큰 게 모델 때문인지 경로가 유난히 어려워서인지" 구분이 안 됨. 같은 경로로 고정해야
6명 간 오차 크기를 공정하게 비교할 수 있음.

## 6. 전원이 검증 데이터 수집에 참여할 필요는 없음 — 일부만 참여

수집 부담을 줄이기 위해 일부 인원만 검증 경로를 걷는다. **참고**: 다만 2번 항목("6명
각자 결과를 낸다")과 결합하면, **검증에 참여하지 않은 사람은 실측 대조가 불가능**하고
모델 예측치만 존재하게 됩니다. 검증 참여자 명단이 정해지면, 나머지 인원은 "예측만 있고
실측 검증은 없음"이라는 걸 발표 자료에 명확히 구분해서 표기하는 게 좋습니다.
